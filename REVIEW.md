# REVIEW.md

Defects found in the starter `app/main.py`. Line numbers refer to the starter as received.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (l.33-37) | Builds shift start with `punch_in.replace(hour=...)` on a UTC/naive value, not IST. | Shift 09:30, punch-in 10:05 IST (04:35Z): start becomes 09:30Z, difference is negative, so late is 0. Nobody is ever late. | Convert to IST first. Shift start is built from the attendance date in IST (`ist_at`). |
| 2 | `compute_late_minutes` (l.36-37) | Floors to minutes *then* tests `> 10`. R2 says strictly more than 10:00. | 09:40:01 gives 10 minutes, which fails `> 10`, so it returns 0 (expected 10). Sub-second input is also not truncated. | Compare whole seconds (`> 600`), then floor to minutes. Instants are truncated to seconds on input. |
| 3 | `compute_late_minutes` (l.34-35) | Ignores overnight shifts; always uses the punch-in's own calendar day. | Shift 22:00-06:00, punch-in 01:00 next day: start is computed as 22:00 *that* day, so negative, so 0. | Shift start is taken on the attendance date (R1), which is yesterday for early-morning punch-ins on overnight shifts. |
| 4 | `compute_work_hours` (l.40-41) | Python `round()` is half-to-even on a float. | 9.125 h (32850 s) returns 9.12; R4 wants 9.13. | Integer seconds and `Decimal` with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` (l.44-47) | No 30-minute minimum; no overnight end on the next day; naive vs aware subtraction. | Punch-out 10 min after shift end returns 10 (expected 0). Overnight shift: end is placed before the start, giving huge overtime. Naive `punch_out` minus aware `end` raises `TypeError`, a 500. | Threshold added, end day shifted for overnight, everything is aware UTC/IST. |
| 6 | `punch_in` (l.101-102) | No 404: `emp` is `None` for an unknown code, so `emp["shift_start"]` raises. | `POST /attendance/punch-in` with `emp_code: "NOPE"` gives a 500. | `get_employee_or_404`. |
| 7 | `punch_in` (l.102-103) | `datetime.fromtimestamp(ms/1000)` uses the *server's* time zone and keeps milliseconds. `if body.punched_at` treats 0 as missing. `date` comes from server-local time, not IST. | Run the server in UTC: a punch at 00:30 IST lands on the previous date. Sub-second values are stored. | `ms_to_dt` (UTC, seconds truncated). Date from `attendance_date` (R1). `is not None` check. |
| 8 | `punch_in` (l.104-120) | Check-then-insert race, and no unique index. | Two parallel punch-ins both pass `find_one` and both insert: two records, two 201s. | Unique index on `(emp_code, date)`; `insert_one` and catch `DuplicateKeyError` for 409. |
| 9 | `PunchInIn` (l.60-63) | `status: str` accepts anything; `punched_at: int` lax-coerces floats and numeric strings; no range. | `status: "ABSENT"` or `"foo"` accepted. `punched_at: "1783312500000"` or `1.5e12` accepted. Seconds-looking values accepted. | `Literal` presence statuses; strict int with the contract's min/max, so 422. |
| 10 | `punch_in` response (l.119-121) | Returns `id` (the ObjectId), raw naive datetimes, not epoch ms. | Response has an `id` field and ISO strings for `punch_in`. Contract forbids both. | `attendance_out` serialises exactly the contract fields, instants as epoch ms. |
| 11 | `list_attendance` (l.125-150) | Loads the whole matching collection into memory, sorts in Python, slices in Python. Sort is by `date` only. | 100k documents per request; slow and memory heavy. Rows on the same date come back in arbitrary order (needs `emp_code` asc). | DB-side `sort` + `skip` + `limit`, `count_documents`, and an index matching the sort `(date desc, emp_code asc)`. |
| 12 | `list_attendance` (l.125-150) | No validation: `page=0` gives a negative slice, `page_size` has no cap, dates and status unchecked, `date_from > date_to` allowed. Legacy docs lack `history`/`half_day`; `id` leaks. | `?page=0`, `?page_size=100000`, `?date_from=2026-07-09&date_to=2026-07-01`, `?status=BAD` all return 200. | `Query(ge/le)`, `Literal` status, date regex plus real-date check, 422 for reversed range; defaults applied in `attendance_out`. |
| 13 | `list_employees` (l.89-96) | `skip = page * page_size` is off by one. `total` counts the whole collection, ignoring `department`. No sort. | Page 1 skips the first page of data. With `department=Eng`, `total` is every employee. Order is not by `emp_code`. | `(page-1)*page_size`, `count_documents(q)`, `sort("emp_code")`, bounds on page and page_size. |
| 14 | `create_employee` (l.77-85) | Same check-then-insert race, no unique index. No input validation. `created_at` is `datetime.now()` (naive, server-local) and returned as a datetime. | Parallel creates give duplicate `emp_code`s. `shift_start == shift_end`, bad email, `joined_on: "2026-02-30"`, `emp_code: "x"` all accepted. | Unique index plus `DuplicateKeyError` for 409. Pydantic patterns for every field, real-date check, shift check. UTC `created_at`, returned as epoch ms. |
| 15 | `health` (l.70-72) | Always returns ok without touching MongoDB. | Stop MongoDB: `/health` still says 200, but the contract says 503. | Pings MongoDB; 503 on failure. |
| 16 | Setup (l.24-25, whole file) | `MongoClient` is not `tz_aware` (naive datetimes), has no server-selection timeout, and **no indexes are created**. | Mixed naive/aware arithmetic (see #5). Every query is a collection scan. | `tz_aware=True`, 5 s timeout, `ensure_indexes()` in the startup lifespan (idempotent, also retried from `/health`). |
| 17 | whole file | A MongoDB error surfaces as an unhandled 500. | Stop MongoDB mid-request. | `PyMongoError` handler returns 503 with `{"detail": ...}`. |

## Looked at and decided it was not a defect

- `load_dotenv()` with its default `override=False` already lets real environment variables win over `.env`, as the contract requires.
- The `HTTPException(409, ...)` status codes themselves are right; only how they were produced (the race) was wrong.
- `doc.pop("_id", None)` in `create_employee` correctly keeps the ObjectId out of the response; the same care was missing in `punch_in` (#10).
- Extra fields in request bodies are ignored by Pydantic's default, which matches "if a client sends a derived field, ignore it".
